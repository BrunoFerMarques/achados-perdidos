## Projeto

O projeto consiste no desenvolvimento, em equipe, de um sistema de software **minimamente complexo**.

> [!IMPORTANT]
> O projeto **não** deve se limitar a uma página estática ou a operações CRUD simples.

O sistema deve possuir regras de negócio e comportamentos que justifiquem a aplicação de práticas de Engenharia de Software, especialmente **testes automatizados**.

### O que o projeto deve possuir (idealmente)

- [ ] Backend com arquitetura organizada e adequada ao problema
- [ ] Frontend que se comunique com o backend
- [ ] Interface de usuário interativa
- [ ] Regras de negócio implementadas e testadas
- [ ] Testes automatizados
- [ ] Controle de versão utilizando Git/GitHub
- [ ] Documentação suficiente para permitir que outras pessoas entendam e executem o projeto

O projeto deve ser desenvolvido de maneira **incremental**, com entregas frequentes ao longo do semestre.

## Equipes

| Item              | Regra        |
| ----------------- | ------------ |
| Tamanho da equipe | 1 a 5 membros |

O tamanho da equipe deve ser levado em consideração na definição do escopo: projetos maiores e mais complexos serão esperados de equipes maiores.

## Desenvolvimento do projeto

Ao longo do semestre, cada equipe deverá manter o projeto em um **repositório GitHub**.

A atividade da equipe no repositório fará parte da avaliação prática.

### Critérios observados na avaliação

Serão observados, entre outros aspectos:

| #  | Critério                                    |
| -- | ------------------------------------------- |
| 1  | Evolução incremental do software            |
| 2  | Frequência e qualidade dos commits          |
| 3  | Organização do trabalho                     |
| 4  | Issues e/ou tarefas                         |
| 5  | Pull requests, quando aplicável             |
| 6  | Code review                                 |
| 7  | Testes automatizados                        |
| 8  | Qualidade do código                         |
| 9  | Capacidade de integrar e entregar mudanças  |
| 10 | Documentação                                |
| 11 | Participação dos membros da equipe          |

> [!NOTE]
> Não será avaliado simplesmente o número de commits. O objetivo é observar a aplicação das práticas de Engenharia de Software discutidas durante o curso.
